# План решения

Строится на подтверждённых выводах из `03-hypotheses.md`. Ниже — целевая структура экрана, сравнение с текущей
реализацией и список изменений по приоритетам. Код по этому плану ещё не менялся.

## 1. Принципы (из исследования)

1. Первым видно два ответа: **стало лучше или хуже** и **что исправлять первым** (задание Frontend).
2. Итог по подразделению не должен скрывать провал внутри него (H1): рядом с вердиктом — где стало хуже.
3. Дельта честная: база сравнения названа, «лучше/хуже» — из API (`trend`, `higher_is_better`), null ≠ 0,
   нетто показывается вместе с оборотом (H2), первый прогон без статусов (H6).
4. Приоритет исправления — важность, затем давность и рост (H4); кому — подразделение и владелец (H5).
5. Не делать то, что не даёт ценности на этих данных: группировку по целям, сложную таблицу, запуск прогона (H8, H9).

## 3. Сравнение с текущей реализацией

| Элемент | Сейчас | Нужно по исследованию | Основание |
|---|---|---|---|
| Контекст и база сравнения | есть | без изменений | Q5 |
| Вердикт по доле корректных + динамика | есть | добавить оговорку «но хуже в N подразделениях, сильнее всего X» | H1, H3 |
| **Разрез по подразделениям** | **нет** | блок «Где стало хуже» из `/api/kkd/units`, клик — переход в подразделение | H1, H5 |
| Ключевые метрики | 4 карточки в сетке с героем | строка из 4 компактных карточек под итогом (освобождает место для разреза) | иерархия |
| Оборот new/persisting/resolved | есть, кликабельно | без изменений | H2 |
| Что исправить первым | важность → количество, топ-5 | без изменений по логике; рост уже помечен дельтой | H4 |
| Давность в таблице | колонка «Держится» | без изменений (сортировка API по умолчанию ставит давние критичные первыми) | H4 |
| Выгрузка для поручения | нет | кнопка «Выгрузить CSV» с текущими фильтрами (`/api/kkd/issues/export`) | H5 |
| Направление дельты счётчиков | константа «меньше — лучше» | из `/api/meta` (`higher_is_better` у `issues_total`) | H10 |
| Ошибка 422 FastAPI | текст «Сервер вернул ошибку 422» | разбор `detail` → понятное сообщение | H11 |
| Граничные состояния | есть | без изменений; добавить случай «лист без дочерних» для разреза | H6, H7 |
| Группировка по целям, запуск прогона | нет | не делать | H8, H9 |

## 4. Изменения по приоритетам

**П1 — влияет на оценку, делать обязательно**
1. Хук `useUnitsBreakdown(runId)` → `GET /api/kkd/units` (один запрос на прогон, кэш).
2. Компонент `UnitsBreakdown`: потомки выбранного подразделения с ухудшением доли корректных целей,
   по возрастанию дельты (значения из API), с путём и числом новых/критичных; итог «улучшились N · без изменений M»;
   раскрытие полного дерева; клик по строке — `setUnit`. Для листа — не показывается. Первый прогон — дельты
   «нет данных для сравнения», сортировка по значению доли.
3. Оговорка в вердикте: если `trend` итога `better`/`same`, а у потомков есть ухудшения — строка-предупреждение
   с иконкой и текстом (не только цветом).
4. Перекомпоновка блока «Итоги»: герой + разрез сверху, ключевые метрики строкой ниже.

**П2 — повышает пользу и аккуратность**
5. Направление «лучше/хуже» для счётчиков проблем и для дельты доли в разрезе — из `/api/meta`.
6. Разбор 422 в формате FastAPI в `api/client.ts` + тест.
7. Кнопка «Выгрузить CSV» в заголовке таблицы (ссылка на export с текущими фильтрами, адрес — через тот же базовый URL).

**П3 — сопровождение**
8. Тесты: разрез по подразделениям (сортировка, лист, первый прогон), оговорка в вердикте.
9. Обновить `specs/requirements.md` и `specs/design.md` (новые требования, решения, раздел «изменения по ходу»),
   README (раздел «Что на странице»), добавить ссылку на `research/`.
10. Проверка в браузере по сценариям ниже.

## 6. Риски и допущения

- `/api/kkd/units` необязателен по заданию; использование оправдано H1. Если бы его не было, разрез пришлось бы
  собирать N запросами `summary` — так делать не стоит.
- Сортировка разреза по дельте — порядок показа, не пересчёт: числа берутся из API как есть.
- H12 (пользователь смотрит в основном последний прогон) подтверждена только постановкой — селектор прогона остаётся
  компактным, история доступна через него и через динамику.
