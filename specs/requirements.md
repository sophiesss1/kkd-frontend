# Требования: страница модуля ККД

## Цель

Руководитель или администратор с первого взгляда понимает две вещи:
1. стало лучше или хуже по сравнению с прошлым прогоном;
2. что исправлять в первую очередь.

Каскадирование из user story задания видно так: метрики и проблемы подразделения API считает вместе со всеми
вложенными (это подписано под названием подразделения), ключевая метрика «Покрытие каскадом», каскадные правила
в приоритетах, уровень цели в карточке проблемы.

## Функциональные требования

| ID | Требование | Источник данных |
|---|---|---|
| F1 | Выбор подразделения (иерархия по `parent_id`) и прогона влияет на всю страницу | `GET /api/meta`, `GET /api/runs` |
| F2 | По умолчанию открыт последний успешный прогон и подразделение `B2B` | `GET /api/runs` |
| F3 | Явно показано, с каким прогоном идёт сравнение (`compared_to_run_id`); если между ними пропущен неуспешный прогон — это написано | `GET /api/runs` |
| F4 | Карточки метрик: значение, прошлое значение, дельта, оценка «лучше / хуже» из `trend` | `GET /api/kkd/summary` |
| F5 | Счётчики new / persisting / resolved кликабельны и открывают список проблем ровно с этим фильтром (остальные фильтры сбрасываются) | `summary.delta` |
| F6 | Разбивка проблем по важности с дельтой; клик открывает список с фильтром | `summary.issues_by_severity` |
| F7 | Блок «Что исправить в первую очередь» — правила с нарушениями: важность ↓, количество ↓ | `summary.issues_by_rule` |
| F8 | Таблица проблем: фильтры по правилу, важности, статусу дельты, поиск, сортировка, серверная пагинация | `GET /api/kkd/issues` |
| F9 | Карточка проблемы в модальном окне: описание, факт и ожидание, рекомендация, история по прогонам | `GET /api/kkd/issues/{id}` |
| F10 | Состояние страницы (подразделение, прогон, фильтры, страница, открытая карточка) хранится в URL | — |
| F11 | Блок «Где стало хуже» рядом с итогом: вложенные подразделения, сильнее всего ухудшившиеся сверху (до 5), строка «улучшились · без изменений»; полное дерево — в окне «Все подразделения»; клик по подразделению открывает его. У подразделения без дочерних блока нет | `GET /api/kkd/units` |
| F12 | Оговорка к итогу: если итог «лучше» или «без изменений», а во вложенных подразделениях есть ухудшения — «но хуже в N подразделениях, сильнее всего — X (дельта)» | `GET /api/kkd/units` |
| F13 | Динамика главной метрики по последним прогонам; клик по столбцу открывает прогон | `GET /api/kkd/trend` |
| F14 | Кнопка «Выгрузить CSV»: проблемы с текущими фильтрами, все страницы | `GET /api/kkd/issues/export` |

## Нефункциональные требования

- Числа и дельты не пересчитываются на фронтенде — выводятся из ответов API как есть.
- Подписи важности, статусов дельты и уровней целей и порядок важности — из справочников `GET /api/meta`, а не копией в коде.
- Цвет не единственный носитель смысла: у важности — значок и слово, у дельты — стрелка, знак и слово.
- Визуал — по `UI-KIT.md`: тема antd из справочника; цвета, размеры шрифтов, межстрочные интервалы, жирность 600
  и радиусы — из CSS-переменных темы, а не числами в компонентах. Текст 14/22, все заголовки — страницы, секций,
  карточек и модалки — 20/600/28 (раздел 3 кита), крупные числа в карточках 24–30px, контролы 32px, карточки
  с радиусом `borderRadiusLG` темы (8px), модалка 28px, отступы кратны 4, подсказки — серые цвета кита.
- Десктоп от 1280px: фильтры списка проблем помещаются в одну строку. Семантическая разметка: `header`, `main`,
  `section` с заголовками без пропуска уровней (и в модальных окнах), списки, кнопки для кликабельных счётчиков.
  Всё, что открывается кликом или наведением (карточка проблемы, подразделение в разрезе и в дереве,
  подсказки с формулой метрики, у столбцов динамики и у «Выгрузить CSV»), доступно с клавиатуры. Имя кнопки для
  экранного диктора — её видимое содержимое (с дельтой и числами) плюс действие; имена на русском, в том числе у
  кнопок antd (закрыть окно, очистить поиск, стрелки пагинации), значки не озвучиваются.
- Ошибка запроса любого блока показывается сообщением с кнопкой «Повторить»: блок не пропадает молча, а «Повторить»
  в любом блоке перезапрашивает всё, что сейчас упало на странице. Ответ не в формате API (адрес API указывает
  не туда) — понятная ошибка. Пустое состояние «проблем нет» показывается только по ответу на текущие фильтры.
- Ссылка не ломает страницу: неизвестные коды фильтров и размер страницы отбрасываются, страница за концом списка
  заменяется последней, у неизвестного подразделения есть выход на подразделение по умолчанию.
- Адрес API — в переменной окружения. Запуск — `docker compose up`.
- Одинаковые запросы не дублируются (общий кэш React Query с единой фабрикой ключей). Разрез по подразделениям —
  один запрос на прогон: смена подразделения его не повторяет.
- Где API не отдаёт `trend` (счётчики проблем, доля в разрезе), оценка «лучше / хуже» берётся из `higher_is_better`
  метрики в `GET /api/meta`; само число дельты — из API.
- Ошибки валидации в формате FastAPI (`{"detail": [...]}`) показываются понятным текстом с именами параметров.

## Критерии приёмки

| # | Дано / Когда | Тогда |
|---|---|---|
| A1 | Открыт `RUN-001` | Вместо дельт — «нет данных для сравнения», статусы дельты в таблице и фильтр статуса отключены; фильтр статуса, оставшийся в URL от другого прогона, не применяется |
| A2 | Выбран `RUN-006` | Показано «Прогон RUN-006 завершился с ошибкой» с причиной и кнопкой перехода на последний успешный прогон; страница не ломается |
| A3 | Выбрано `TX-NEW` | Пустое состояние «нет активных целей», нули не выдаются за метрики |
| A4 | Выбрано `CIB-REG`, последний прогон | Главная карточка «Стало хуже», доля корректных целей упала, в приоритетах — каскадные правила |
| A5 | Открыт `RUN-007` | Плашка: сравнение с `RUN-005`, `RUN-006` пропущен из-за ошибки |
| A6 | Клик по «Исправлены» | Таблица отфильтрована по `delta_status=resolved`, страница прокручена к списку |
| A7 | Фильтр без результатов | «По выбранным фильтрам проблем нет» и кнопка сброса |
| A8 | Mock API недоступен | Примерно через 12 с (три попытки), а не через минуты — сообщение об ошибке с кнопкой «Повторить» |
| A9 | Смена подразделения/прогона/фильтра, поиск | Без перезагрузки страницы, URL обновлён, «назад» возвращает прошлое состояние; поиск добавляет одну запись истории, а не запись на каждую паузу в наборе; повторный клик по уже выбранному (счётчик, прогон, показанный столбец динамики) записи не добавляет |
| A10 | Рост числа проблем | Помечается «хуже» (красный + стрелка вверх + слово), рост доли корректных целей — «лучше» |
| A11 | `B2B`, `RUN-008` | Вердикт «Стало лучше», под ним «но хуже в 5 подразделениях, сильнее всего — Управление региональных продаж (−25,5 п.п.)» |
| A12 | Блок «Где стало хуже», клик по `CIB-REG` | Страница переключается на `CIB-REG` без перезагрузки, URL обновлён |
| A13 | Выбрано подразделение без дочерних (`TX-SAL`) | Блока «Где стало хуже» нет, на его месте ключевые метрики; «Нарушений правил нет» |
| A14 | `RUN-001` | В разрезе — «нет данных для сравнения», без «лучше / хуже», сверху подразделения с наименьшей долей |
| A15 | «Выгрузить CSV» с фильтром «Критичная» | Скачивается CSV только с критичными проблемами текущего подразделения и прогона; пока список грузится, кнопка выключена |
| A16 | Открыта страница, затем выбрано другое подразделение того же прогона (в том числе позже чем через минуту и после подразделения без дочерних) | `GET /api/kkd/units` за всё время — один запрос |
| A17 | Ссылка с `?page=10` у `B2B`, `RUN-008` (61 проблема, 20 на странице) | Открывается последняя, четвёртая страница, а не «Проблем не найдено» |
| A18 | `GET /api/kkd/trend` отвечает ошибкой | В главной карточке вместо динамики — сообщение с кнопкой «Повторить», остальная страница работает |
| A19 | Ссылка `?unit=XYZ` (подразделения нет) | «Подразделение XYZ не найдено» и кнопка «Открыть „Корпоративный блок“» |
| A20 | Ссылка `?severity=foo&size=500&rule=UNKNOWN` | Неизвестное отброшено: список без этих фильтров, 20 на странице, ошибки 422 нет |
| A21 | Набран поиск и сразу нажато «Сбросить фильтры» | Поле поиска пустое, набранный текст после сброса не применяется |

A11, A12, A16, A19 и часть A15 (кнопка выключена во время загрузки, адрес выгрузки с фильтром) закреплены тестом
`src/features/kkd/KkdPage.test.tsx` на сохранённых ответах mock API; содержимое CSV отдаёт сам API. A16 проверяется
переходом B2B → CIB-REG (без дочерних) → через 61 с HQ-CIB (с дочерними). Там же — клик по показанному столбцу
динамики (A9) и сообщение, когда нет ни одного успешного прогона.
Тест `src/features/kkd/components/IssuesSection.test.tsx` закрепляет фильтр статуса в первом прогоне (A1),
запись истории при поиске, в том числе с уходом из поля раньше задержки (A9), A17, A21, неизвестное правило из A20,
пустое состояние во время загрузки и русские имена кнопок antd. Он же проверяет, что название проблемы — нативная
кнопка с фокусом. Нажатие Enter в jsdom не проверить, у нативной кнопки оно вызывает клик: это проверено
в браузере. Повторный клик из A9 и отбрасывание кодов и размера из A20 — `src/features/kkd/useKkdParams.test.ts`.
A18 — `src/features/kkd/components/TrendBars.test.tsx`.
